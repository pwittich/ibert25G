SLIDE 01
Audience: experimental particle physicists and detector/readout engineers. Suggested talk duration: 25 minutes, followed by the three backup slides. The motivation is reproducible physical-link measurement before detector framing and application traffic. The current candidate is an autonomous managed-GTY PRBS engine, not a vendor IBERT core. All architecture and performance numbers in this talk are specific to the recorded VU13P build and bench evidence.

SLIDE 07
Each FPGA owns 112 GTY channels in 28 quads: 56 optical FireFly lanes and 56 nominal direct FPGA-to-FPGA lanes. The direct test uses 54 fitted receivers per endpoint; F1 global70/71 and F2 global96/97 are omitted. The 2.8875-Tb/s figure is nominal aggregate TX capacity per FPGA, not an all-channel measured result.

SLIDE 08
Explain the partition in familiar detector terms: host run control, an embedded supervisory endpoint, and a deterministic hardware instrument. MicroBlaze polls for a new mailbox request when idle, validates it and programs the engine. During the acquisition/measurement job it sleeps until the engine interrupt; it does not poll individual lanes. Bounded polling for TX-session application acknowledgement exists in the session control path. The HDL engine and per-lane logic own timing, acquisition, native counters, CDC and immutable publication.

Evidence: src/gt_test_engine_core.sv; firmware/gt_test_milestone2.c; scripts/all_links_v2_timed_common.py

SLIDE 09
This is a logical block diagram of the actual all-links v2 image, repeated at F1 and F2. The board MCU and its I2C5/mux path are outside the FPGA boundary. The generic 0x2B I2C frontend reads the existing clock monitor below byte address0xA0 and accesses the engine hardware mailbox and published result window above it. This byte path bypasses MicroBlaze. MicroBlaze is an AXI4-Lite master that validates jobs, writes descriptors and handles engine completion, not a software I2C server. Its32-KiB BRAM contains the ELF as bitstream initialization data; MDM provides JTAG debug. Engine completion drives both interrupt and wakeup. The engine includes management-domain control and RX-domain lane measurement logic, so the outline is not a single synchronous clock domain. Explicit CDC handshakes bring coherent lane snapshots to banked management-domain result storage. The four SLR banks contain28 quad controllers distributed6/8/8/6 and manage112 GTY channels. TX and RX PRBS primitives and the DRP error counters are native GT resources. Twelve physical REFCLK0 buffers supply the managed-GT topology. Fabric control runs at200MHz and the monitored100/325MHz clocks come from the MMCM. Arrows are grouped functional interfaces, not a full pin-level netlist or a physical floorplan. Both MCU and MicroBlaze access hardware registers through separate frontends; no high-speed event data traverses I2C or the soft CPU.

Evidence: src/gt_test_direct_quad_v6_core.sv; src/gt_test_engine_core.sv; scripts/create_all_links_v2_project.tcl

SLIDE 10
The operator may SSH to Linux on the blade. Python sends ASCII FP transactions over the MCU UART, /dev/ttyUL4 on this blade. The MCU selects exactly one FPGA through the 0x70 I2C mux and holds the I2C5 software semaphore for the full transaction. The generic fabric slave is a 7-bit address 0x2B on either FPGA. FPGA selection is outside the register address space. Preserve this access discipline: two actors sharing the UART or mux can otherwise corrupt the apparent transaction context. JTAG/XVC is a separate programming/debug route, not the timed measurement transport.

SLIDE 12
The host writes command, duration, timeout and the 112-bit mask first and verifies each field. It writes the new request sequence last. MicroBlaze accepts a changed sequence, validates the fields, copies them to the executable AXI descriptor and rings one doorbell. A matching response sequence identifies completion. Run IDs identify receive publications; session start and stop do not consume a receive run. The result bank is immutable until a new publication. Software compares run ID across multi-transaction collection. The operator scripts now discover predecessor values while holding the MCU lock. Explicit expected-state guards remain optional for automation; rerunning an unguarded command is a new test, not a resume operation.

Evidence: scripts/all_links_v2_timed_common.py; firmware/gt_test_milestone2.c

SLIDE 13
The generated subsystem has one MicroBlaze v11 core at 200 MHz, 32 KiB of local instruction/data BRAM through the local memory buses, no caches and no operating system. It has one AXI4-Lite master to the test engine at 0x44A00000. One level-sensitive engine interrupt drives both the Interrupt input and Wakeup[0], so a sleeping core actually resumes. The fixed 0x10 interrupt vector services that source and clears the pending level. MDM provides JTAG debug and a second wakeup source. This avoids a full software platform, external DDR, an AXI interrupt controller, and timing-sensitive software polling of the measurement datapath.

Evidence: scripts/create_milestone3_project.tcl; firmware/gt_test_milestone2.c and .ld

SLIDE 14
The reproducible build compiles startup assembly and C with matching MicroBlaze little-endian flags and a fixed linker script. The linker places the reset and interrupt vectors, text, data and stack in local BRAM. Tcl adds exactly one matching ELF, scoped to gt_test_milestone3_bd and microblaze_0. The software becomes BRAM initialization contents in the built design. The audited routed checkpoint produces the compressed bitstream. Configuration initializes the memories, releases reset and starts the processor. Thus Hardware Manager and XSDB both load the firmware when programming this exact BIT; a separate debugger download is not needed. The programmer verifies the standalone ELF hash as provenance, but its programming command is just fpga -file. A BIT made without this ELF association would be a different case.

Evidence: scripts/build_all_links_v2_firmware.sh; scripts/create_all_links_v2_project.tcl; bit-generation Tcl

SLIDE 15
Startup noise must not enter the physics-style exposure denominator. The managed quad sequence stages TX before RX acquisition, retains a fixed 200,000-cycle or one-millisecond observation, and resets native error counters after acquisition/lock. Only then does the requested timed measurement start. External mode keeps LOOPBACK=000 and avoids resetting an already live RX datapath by default. At capture, native error counters are read through DRP and RX requalification completes before publication/cleanup. Acquisition diagnostics remain readable through idle. Near-end PMA loopback uses 010 and a bounded reset sequence; it bypasses the optical path and is a different test.

Evidence: src/gt_test_direct_quad_v6_core.sv; docs/gt-test-engine.md; AGENTS.md, managed-quad behavior

SLIDE 16
Each lane returns eight 32-bit words: lane/status, 64-bit error field, 64-bit tested bits, native lock losses and 64-bit valid RX cycles. The error ABI is 64 bits, but the exact native GT PRBS error count is a 32-bit saturating counter zero-extended into that field; do not infer 64-bit native dynamic range. The native DRP count comes from 0x25E/0x25F. Tested bits equal 80 times valid RX user-clock cycles. The 80-bit parallel interface at 322.265625 MHz corresponds to 25.78125 Gb/s. Results transfer coherently and the host-visible BRAM bank remains immutable until the next complete publish. Native lock-loss counters do not prove that a link was free of optical disturbances or PRBS errors.

Evidence: docs/gt-test-engine.md, lane record; src/all_links_v2_result_copy_bank.sv; timed-test validators

SLIDE 17
A VU13P is a large multi-die FPGA. Four SLR banks distribute 28 quads in a 6/8/8/6 pattern. Each quad has its own receive-clock behavior; signals cannot be treated as synchronous to the management clock. The final v2 design transfers each 256-bit lane snapshot as four stable 64-bit handshakes, registers four result-copy banks and releases reset locally with matched latency. The participation mask derives from the accepted receive-lane descriptor. Only acquisition-ready and capture-done reductions neutralize unselected quads. All-quad readiness, fault, reset, idle and TX-session barriers remain intact. V1 incorrectly waited for unselected quads during direct-only acquisition; v2 fixes that functional deadlock without bypassing safety-related barriers.

Evidence: docs/all-links-v2-timing-strategy.md; src/all_links_v1_slr_bank.sv; v2 routed audit

SLIDE 18
Show worst setup slack as an engineering diagnostic, not a benchmark. The original v2 route missed setup by 0.158 ns; reuse of the audited v1 route still missed by 0.119 ns. The successful change was architectural: registered result banks, narrower CDC transfers and local reset release. Only true control/reset boundaries are hard-contained; publication-only data placement stays soft. Large hard pblocks and speculative timing exceptions were not the solution. The final audit has setup +0.046 ns, hold +0.009 ns, no failing endpoints, 220150 fully routed nets, zero routing/Error-DRC failures and all 476 bus-skew groups meeting. These margins qualify the exact archived implementation, not an arbitrary rebuild.

Evidence: docs/all-links-v2-timing-strategy.md; timing-hardened independent audit

SLIDE 19
No single test proves the whole system. Functional regressions test direct-only, sparse and all112 selections, changed epochs and session barriers. Synthesis/preflight proves the intended exact inventory: 112 channels, 28 commons/controllers, twelve managed REFCLK buffers, 112 engines, no IBERT or C2C ownership overlap. An independent routed audit checks GT properties against the golden reference, physical reset/participation locality, dedicated reference-clock routing, CDC structure and timing exceptions. The FPGA state-machine encodings are ABI and are protected from recoding. Hashes bind the ELF, checkpoints, BIT and source evidence. Finally the hardware test measures actual links; the earlier checks cannot replace it.

SLIDE 20
The procedure verifies image identity, healthy idle/session-off state and stable predecessor sequence/run. Updated scripts discover those counters under the MCU lock; explicit expected-state guards remain optional. It logs all clocks and requires 200/100/325-MHz fabric and all twelve 322-MHz managed references. Before starting it records board-wide power and temperatures. Session start on both sites uses a 240-second lease for a 180-second measurement. The session application acknowledgement is required before RX measurement. The host observes both FPGAs simultaneously in RUN and takes telemetry near one-third and two-thirds of the window. It validates complete per-lane publications, then issues normal session stops. The MCU is serialized, and logs survive pass or failure. The command is never automatically retried: an uncertain link to the host must not replay a hardware action.

Evidence: scripts/all_links_v2_timed_common.py; 2026-10-27 180-second evidence log

SLIDE 21
For a stationary independent rare-error model, the probability of zero errors is exp(−BER*N). Setting this to 0.05 gives a one-sided 95% upper bound −ln(0.05)/N. Use the observed valid-bit denominator rather than simply multiplying nominal rate by wall-clock runtime. Taking the smallest observed lane denominator, N=4640547042800, gives 6.4556e-13. This bound is per lane. Pooling all 108 paths would require an additional common-rate model and is deliberately not done here. Burst errors, startup dependence, pattern dependence and changing conditions require separate studies.

Evidence: Derived from actual tested-bit counts in the 180-second log; one-sided Poisson zero-count limit

SLIDE 24
The receive mask and TX-session mask are intentionally distinct in the current interface. Firmware accepts TX sessions only with all112 managed transmitters selected, on each FPGA. Therefore even a q221–q234 direct-only measurement emits PRBS31 out of all FireFly transmitters. Operators must confirm the connected optical equipment can safely receive it. The FireFly CLI accepts arbitrary quad sets within q121–q134 symmetrically on both sites; the direct CLI currently measures its fixed fitted masks. Arbitrary direct subsets, mixed groups and different optical sets per endpoint need a reviewed CLI extension. Session-off restores the normal no-PRBS session state; it is not a physical FireFly-disable operation. Native lock-loss counters cannot exclude all optical disturbance modes.

Evidence: HOWTO.md; scripts/all_links_v2_timed_contract.py; firmware TX-session validation

SLIDE 25
Close with three claims supported by the evidence. First, the parallel hardware engine gives explicit acquisition and valid-exposure semantics independent of host scheduling. Second, an I2C mailbox and a small embedded supervisor provide integration without a full CPU platform, while allowing both Hardware Manager and XSDB to load the same firmware-bearing BIT. Third, the exact audited image has measured all54 fitted direct receivers at both endpoints cleanly for180 seconds, with per-lane95% zero-error limits around6.46e-13 under the stated model. The next engineering work is independent TX-class control, a general direct/mixed selector, and targeted optical-path investigation followed by longer BER runs under chosen conditions. These are proposed improvements, not already demonstrated capabilities.

SLIDE 26
All locations shown are byte addresses in the generic I2C slave. Each word is little-endian. The receive command used in the timed direct and optical procedures is0x00010501: parallel BER opcode, PRBS31, external LOOPBACK=000 and millisecond timebase. Session start is command2, session stop3; they require all112 mask bits and do not advance receive run ID. Selector0xFE exposes live and retained first-fault platform diagnostics at0xD0–0xEC. The normal lane and clock ABI addresses are unchanged. The wide command and response interface is owned by hardware and firmware jointly; direct low-level writes should follow the operator scripts rather than an ad hoc byte sequence.

SLIDE 27
The 37 clock-monitor values are direct-kHz counts relative to the board200-MHz oscillator; entry0 reports the configured nominal reference. They are not an external precision frequency standard. The required managedGT references are registers r11,r12,r14–r23; not every visible REFCLK1 monitor is a required clock for this image. The MCU runtime page0x06 offset0x15 gives raw active-low DONE pins: bit0F1, bit1F2. A low bit means configured. The library enum exposes raw levels and must not be interpreted as active-high configuration status. DONE does not identify which image is running. Read firmware and hardware versions as well. The F2 XSDB load emitted PROGRAM_F2_COMPLETE and showed MicroBlaze running, then crashed during shutdown with Tcl_FindHashEntry on deleted table. Independent MCU/I2C checks and the completed subsequent PRBS test establish loaded behavior; no programming retry was made.
